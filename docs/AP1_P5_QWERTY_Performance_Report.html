1. Pendahuluan dan Tujuan Audit

Pengembangan aplikasi berbasis web skala modern menuntut keseimbangan antara penambahan fungsionalitas dan pemeliharaan kinerja aplikasi yang cepat serta responsif. Pada tahapan sebelumnya, Kelompok QWERTY telah menyelesaikan implementasi PWA minimal (Tugas 5a) yang mencakup web app manifest, ikon adaptif, service worker untuk offline fallback, dan strategi cache aset, serta implementasi Component Library (Tugas 5b) yang merombak antarmuka menggunakan komponen reusable berstandar aksesibilitas (Button, Card, dan FormField).

Tujuan dari audit performa ini adalah untuk mengukur secara obyektif dampak teknis dari kedua implementasi tersebut terhadap metrik kunci kinerja web yang diakui secara global (Google Web Vitals), menganalisis perubahan ukuran berkas bundel (bundle size), memvalidasi kepatuhan aksesibilitas web (WAI-ARIA), serta mendokumentasikan hasil pengujian secara transparan berbasis berkas data hasil audit riil.

2. Metodologi dan Kondisi Lingkungan Pengujian

Pengujian dilakukan pada build produksi aplikasi menggunakan protokol pengujian otomatis Google Lighthouse CLI yang dijalankan di atas server lokal produksi:

  • Perintah Kompilasi Build: npm run build (menjalankan tsc -b && vite build) — selesai dalam waktu 545 ms.
  • Server Audit: npm run preview (server vite preview) pada URL target http://localhost:4173/.
  • Alat Audit Resmi: Google Lighthouse CLI versi 13.5.0 (didukung engine aksesibilitas axe-core 4.14.0).
  • Mesin Browser: Google Chrome Headless versi 155.0.0.0 pada sistem operasi 64-bit Windows.
  • Profil Emulasi Perangkat: Mobile (Moto G Power 2022, dimensi viewport 412 × 823 piksel, rasio piksel perangkat / DPR 1.75).
  • Metode Simulasi (Throttling): Simulasi baku Lighthouse (Lantern Simulation) dengan pelambatan CPU 4× (CPU slowdown multiplier), latensi jaringan RTT 150 ms, dan throughput unduh 1.638,4 Kbps (~1,6 Mbps).
  • Waktu Pengujian Riil: Baseline: 18 Oktober 2026, 23:17 WIB (2026-10-18T16:17:23.455Z)  |  Post-Tugas 5: 19 Oktober 2026, 00:44 WIB (2026-10-18T17:44:27.250Z)
Catatan Komparabilitas Konfigurasi & Batasan Audit

Pemeriksaan menyeluruh terhadap objek configSettings pada kedua berkas JSON membuktikan kesetaraan konfigurasi 100%. Sesuai aturan standar Lighthouse (clearStorageTypes: ["service_workers", "cache_storage", ...]), cache browser dibersihkan sebelum pengujian. Dengan demikian, audit mengukur kondisi kunjungan pertama (first-load) dan tidak mengukur secara langsung manfaat caching Service Worker pada kunjungan ulang atau mode offline. Indeks benchmark CPU mesin tercatat 1589 pada baseline dan 1471 pada pengujian terkini (selisih ~7,4% akibat fluktuasi beban sistem operasi lokal Windows).

5. Analisis Kritis Berbasis Bukti Audit

1. Peningkatan Signifikan Skor SEO (+9 Poin: 82 → 91)

Kenaikan skor SEO dibuktikan secara nyata oleh audit Lighthouse pada audit meta-description. Pada baseline awal, aplikasi belum memiliki tag deskripsi sehingga mendapat skor 0 (gagal). Pada implementasi Tugas 5a PWA, penambahan <meta name="description" content="Share.Bill - Split bills based on what everyone ordered." /> ke dalam berkas index.html menyebabkan audit ini berstatus lulus sempurna (skor 1). Skor belum mencapai 100 karena audit robots-txt bernilai 0 (server SPA Vite preview mengembalikan dokumen fallback index.html saat Lighthouse meminta /robots.txt).

2. Evaluasi Metrik Waktu & Total Blocking Time (TBT)

Dalam mengevaluasi perubahan skor Performance dari 100 ke 99 serta pergeseran TBT dari 7,0 ms (tampilan 10 ms) ke 54,5 ms (tampilan 50 ms), penting untuk membedakan antara fakta hasil pengamatan audit dengan hipotesis teknis penyebabnya:

A. Fakta Hasil Pengamatan Audit (Audit Observations):

  • TBT terukur bergeser dari 7,0 ms ke 54,5 ms, namun tetap berada dalam batas rekomendasi aman Google (di bawah 200 ms).
  • Data rincian kerja thread utama (mainthread-work-breakdown) mencatat kenaikan durasi pada kategori scriptEvaluation (+105,8 ms, dari 90,4 ms ke 196,2 ms) dan styleLayout (+21,1 ms, dari 140,1 ms ke 161,2 ms).
  • Nilai indeks benchmark komputasi mesin lokal tercatat berbeda antara kedua pengujian (1589 pada baseline vs 1471 pada pengujian terkini, selisih ~7,4%).
  • Log audit jaringan menunjukkan tidak ada proses eksekusi thread sw.js selama audit navigasi karena seluruh storage dan service worker dibersihkan sebelum pengujian oleh setelan clearStorageTypes.

B. Dugaan / Hipotesis Teknis yang Masuk Akal (Technical Hypotheses):

  • Kenaikan waktu pada scriptEvaluation dan styleLayout menjadi indikasi yang ditemukan pada audit mengenai potensi beban komputasi tambahan. Namun, temuan ini tidak dapat dinyatakan sebagai bukti mutlak bahwa komponen Button, Card, atau CSS merupakan penyebab tunggal, mengingat adanya interaksi dinamis modul lain serta perbedaan lingkungan eksekusi.
  • Fluktuasi daya komputasi mesin lokal (tercermin dari indeks benchmark yang ~7,4% lebih rendah) berpotensi memengaruhi algoritma simulasi pelambatan CPU (Lantern) dalam memproyeksikan metrik waktu ke perangkat mobile.
  • Kenaikan TBT tidak dapat disimpulkan sebagai akibat dari Service Worker, karena tidak ditemukan jejak aktivitas Service Worker pada trace kerja thread utama selama audit berlangsung.

3. Kestabilan Tata Letak (Cumulative Layout Shift = 0)

Skor CLS tercatat 0,000 tanpa pergeseran. Hal ini membuktikan bahwa komponen Card dan FormField yang dibangun pada Tugas 5b memiliki struktur CSS yang solid dan tidak menimbulkan lonjakan visual dinamis saat elemen antarmuka selesai dimuat pada skenario pengujian ini.

4. Analisis Aksesibilitas (Skor 94 Tetap Konsisten)

Skor Accessibility secara keseluruhan berada pada angka 94 (skala 100), stabil sama persis dengan kondisi baseline awal. Berdasarkan laporan audit otomatis Lighthouse (axe-core) pada halaman Beranda, skor Accessibility tertahan di 94 bukan karena isu struktur semantik baru, melainkan karena masih adanya temuan rasio kontras warna (color-contrast, skor 0) sebesar 3.76:1 pada teks tombol utama hijau emerald #059669 terhadap putih dan tautan navigasi aktif .nav-link.active, di mana standar WCAG AA merekomendasikan rasio minimal 4.5:1 untuk teks berukuran normal (14px).

7. Keterbatasan Metodologi Pengujian

  1. Skenario First-Load Saja: Pengujian otomatis Lighthouse secara default menghapus cache dan mematikan Service Worker aktif untuk mengevaluasi kondisi pengguna baru pertama kali. Pengujian ini tidak mencerminkan secara langsung kecepatan pembacaan cache Service Worker pada kunjungan ulang (repeat visit) maupun kesiapan fallback saat koneksi terputus total (offline mode).
  2. Variasi Lingkungan Mesin Lokal: Pengukuran dijalankan pada lingkungan mesin pengembang lokal (laptop Windows) dengan fluktuasi benchmark CPU (1589 vs 1471). Pengujian di lingkungan Continuous Integration (CI) berbasis cloud akan memberikan angka yang lebih konstan.

8. Rekomendasi Teknis Lanjutan

  • Penyempurnaan SEO Menuju 100: Menambahkan berkas statis public/robots.txt sederhana dengan instruksi User-agent: * Allow: / agar server preview tidak mengembalikan dokumen HTML fallback.
  • Penyempurnaan Aksesibilitas Menuju 100: Menyesuaikan tone warna teks primer menjadi #047857 (Deep Emerald) yang memiliki rasio kontras > 4.5:1 terhadap latar putih untuk memenuhi seluruh kriteria WCAG AA.

9. Kesimpulan Akhir

Berdasarkan audit performa komparatif antara kondisi baseline awal dan kondisi terkini setelah pengerjaan Tugas 5a (PWA) dan Tugas 5b (Reusable Components) pada proyek Share.Bill oleh Kelompok QWERTY, dapat disimpulkan bahwa:

  1. Kinerja Aplikasi Berada pada Tingkat yang Stabil: Skor Performance tercatat pada level 99 dengan seluruh metrik Core Web Vitals (FCP 1,5 detik, LCP 1,6 detik, TBT 50 ms, CLS 0) berada di dalam ambang batas yang direkomendasikan Google pada skenario first-load yang diuji.
  2. Pertambahan Ukuran Berkas Terkendali: Penambahan tiga komponen antarmuka modular beserta stylesheet menghasilkan pertambahan ukuran transfer HTTP JS+CSS sebesar +1,64 kB (+1,97%) dan pertambahan ukuran raw sebesar +5,35 kB (+2,05%).
  3. Peningkatan SEO Terkonfirmasi: Penambahan metadata deskripsi PWA secara terukur meningkatkan skor SEO sebesar +9 poin (dari 82 menjadi 91).
  4. Stabilitas Tata Letak Terjaga: Cumulative Layout Shift bernilai 0 membuktikan tidak adanya pergeseran tata letak visual saat elemen dimuat pada sesi pengujian ini.
  5. Cakupan Pengujian Terbatas: Perlu dicatat bahwa evaluasi ini berfokus pada kondisi kunjungan awal (first-load) dan belum mengukur dampak efisiensi caching Service Worker saat kunjungan ulang maupun kondisi tanpa jaringan (offline).

Dengan demikian, data pengujian yang diperoleh menunjukkan bahwa implementasi Tugas 5a dan Tugas 5b dapat diintegrasikan dengan penambahan beban sumber daya yang terkelola dengan baik dalam batasan pengujian yang telah dilakukan.
