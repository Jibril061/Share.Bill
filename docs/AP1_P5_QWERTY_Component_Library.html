1. Pendahuluan dan Tujuan

Pengembangan aplikasi berbasis web skala modern menuntut konsistensi visual, efisiensi penulisan kode, serta kemudahan dalam proses pemeliharaan berkelanjutan. Pada pengerjaan Tugas 5b Mata Kuliah Application Project 1 (AP1), Kelompok QWERTY mengimplementasikan sistem Component Library yang berfokus pada pembangunan tiga komponen fondasi antarmuka: Button, Card, dan FormField.

Tujuan utama dari pembuatan component library ini meliputi:

  • Konsistensi Desain Antarmuka: Menjamin seluruh halaman dalam aplikasi menggunakan ukuran, warna, radius border, dan spasi yang seragam.
  • Prinsip Reusability & DRY (Don't Repeat Yourself): Mencegah duplikasi kode HTML dan deklarasi CSS yang berulang di setiap halaman.
  • Aksesibilitas Terstandarisasi (WAI-ARIA): Mengintegrasikan relasi label, penanganan galat interaktif, teks bantuan, dan navigasi fokus keyboard secara native di dalam komponen.
  • Keamanan Tipe Data (Type-Safety): Memanfaatkan TypeScript interface untuk memastikan setiap properti yang diteruskan ke komponen terdefinisi secara ketat dan mencegah kesalahan saat fase kompilasi.

2. Gambaran Singkat Aplikasi Share.Bill

Share.Bill adalah aplikasi Single Page Application (SPA) yang dirancang untuk mempermudah penghitungan pembagian tagihan (split bill) secara transparan dan adil berdasarkan rincian menu yang dipesan oleh setiap individu.

Aplikasi ini dikembangkan dengan arsitektur modern berbasis React 19, TypeScript, Vite 8, dan React Router 8. Aplikasi memiliki alur navigasi client-side yang mencakup halaman Beranda (/), formulir pembuatan tagihan (/create-bill), serta penanganan rute tidak ditemukan (*). Seluruh komponen antarmuka yang dibangun dirancang agar terintegrasi secara modular pada halaman-halaman tersebut.

4. Dokumentasi Komponen Button

Berkas sumber: src/components/Button.tsx & src/styles/components.css.

Komponen Button dirancang untuk menangani seluruh aksi interaktif pengguna dengan dukungan variasi tema visual, variasi ukuran, lebar penuh, serta status nonaktif (*disabled*).

Spesifikasi Properti (Props)

Nama Prop Tipe Data Wajib/Opsional Default Keterangan
variant 'primary' | 'secondary' Opsional 'primary' Menentukan varian visual (primary hijau atau secondary putih berbingkai).
size 'sm' | 'md' | 'lg' Opsional 'md' Menentukan padding dan ukuran font tombol.
fullWidth boolean Opsional false Mengubah lebar tombol menjadi 100% dari elemen pembungkus.
disabled boolean Opsional false Menonaktifkan interaksi, mengatur opacity 0.55, dan aria-disabled="true".
type 'button' | 'submit' | 'reset' Opsional 'button' Atribut perilaku tombol HTML.
children React.ReactNode Wajib - Konten label teks atau elemen di dalam tombol.
...rest ButtonHTMLAttributes Opsional - Mendukung event handler standar seperti onClick, id, dan title.

Variasi dan State

  • Primary: Background #059669, teks putih. Digunakan pada tombol aksi penting (misal Buat Tagihan).
  • Secondary: Background #ffffff, border #d1d5db, teks #374151. Digunakan pada aksi penambahan data.
  • State Disabled: Menerapkan pointer-events: none, opasitas 0.55, kursor not-allowed, dan mencegah eksekusi fungsi onClick.

Contoh Kode Pemakaian

import Button from '../components/Button'

// Tombol Primary (Aksi Utama Navigasi)
<Button variant="primary" type="button">
  Buat Tagihan
</Button>

// Tombol Secondary (Aksi Pendukung)
<Button variant="secondary" type="button" onClick={handleAddMember}>
  + Tambah Anggota
</Button>

// Tombol Status Disabled (Kalkulasi Belum Siap)
<Button variant="primary" disabled title="Lengkapi data terlebih dahulu">
  Hitung Tagihan
</Button>

Batasan: Belum menyediakan animasi spinner otomatis untuk proses asynchronous (*loading state*).

5. Dokumentasi Komponen Card

Berkas sumber: src/components/Card.tsx & src/styles/components.css.

Komponen Card berfungsi sebagai kontainer semantik yang membungkus konten dalam satu kesatuan visual yang rapi, dilengkapi dengan header terstruktur untuk judul dan subjudul.

Spesifikasi Properti (Props)

Nama Prop Tipe Data Wajib/Opsional Default Keterangan
title React.ReactNode Opsional undefined Judul kartu. Jika berupa string, otomatis dibungkus elemen <h2 class="card-title">.
subtitle React.ReactNode Opsional undefined Teks keterangan penjelas di bawah judul kartu.
headerAction React.ReactNode Opsional undefined Slot tombol aksi di sudut kanan atas header kartu.
as 'section' | 'article' | 'div' Opsional 'section' Tag semantik HTML yang digunakan sebagai kontainer luar.
className string Opsional '' Nama kelas CSS tambahan untuk kebutuhan styling khusus.
children React.ReactNode Wajib - Konten isi atau elemen tubuh kartu (card body).

Variasi dan Tata Letak

  • Card Bertitel: Merender kartu dengan area header judul tegas bergaris pemisah visual lembut.
  • Card Polos: Menampilkan pembungkus kartu berbingkai tanpa header jika title tidak disertakan.
  • Responsivitas: Padding otomatis menciut dari 24px (desktop) menjadi 18px pada resolusi sempit (≤ 600px).

Contoh Kode Pemakaian

import Card from '../components/Card'
import Button from '../components/Button'

<Card title="Daftar Menu" subtitle="Tambahkan menu, harga, dan orang yang memesan">
  <p>Daftar menu pesanan bersama akan tercantum di sini.</p>
  <Button variant="secondary" type="button">
    + Tambah Menu
  </Button>
</Card>

Batasan: Belum memiliki slot terstruktur mandiri untuk footer kartu (misal Card.Footer).

6. Dokumentasi Komponen FormField

Berkas sumber: src/components/FormField.tsx & src/styles/components.css.

Komponen FormField membungkus elemen input teks lengkap dengan label, indikator wajib (*required asterisk*), deskripsi bantuan (*helper text*), dan pesan galat (*error alert*). Komponen ini secara ketat mematuhi spesifikasi aksesibilitas web WAI-ARIA.

Spesifikasi Properti (Props)

Nama Prop Tipe Data Wajib/Opsional Default Keterangan
label string Wajib - Teks label yang terhubung langsung ke input melalui htmlFor={id}.
id string Opsional useId() ID elemen input. Jika tidak diisi, dibuat otomatis via React useId().
helperText string Opsional undefined Teks panduan abu-abu di bawah input, terhubung via aria-describedby.
error string Opsional undefined Pesan kesalahan merah dengan role="alert" dan pemicu bingkai merah.
required boolean Opsional false Menampilkan tanda bintang merah * dan atribut native required.
disabled boolean Opsional false Menonaktifkan input dan memberikan styling latar abu-abu redup.
labelSuffix React.ReactNode Opsional undefined Slot elemen tambahan di samping kanan label teks.
...inputProps InputHTMLAttributes Opsional - Mendukung value, onChange, onBlur, placeholder, dll.

Fitur Aksesibilitas (WAI-ARIA)

  • Relasi Semantik: Tag <label> memiliki atribut htmlFor yang identik dengan atribut id pada tag <input>.
  • Indikasi Kesalahan: Saat prop error terisi, input otomatis memperoleh atribut aria-invalid="true" dan aria-describedby="{id}-error".
  • Pengumuman Screen Reader: Elemen pesan kesalahan memiliki role="alert" agar langsung diumumkan kepada pengguna pembaca layar ketika validasi gagal.
  • ForwardRef: Menggunakan React.forwardRef agar kompatibel dengan pengelolaan fokus DOM manual maupun form library.

Contoh Kode Pemakaian

import { useState } from 'react'
import FormField from '../components/FormField'

function FormInputBill() {
  const [name, setName] = useState('')
  const [touched, setTouched] = useState(false)
  const isError = touched && name.trim() === ''

  return (
    <FormField
      id="bill-name"
      label="Nama tagihan"
      placeholder="Contoh: Makan bersama"
      value={name}
      onChange={(e) => setName(e.target.value)}
      onBlur={() => setTouched(true)}
      error={isError ? 'Nama tagihan wajib diisi.' : undefined}
      helperText={!isError ? 'Beri nama untuk mengidentifikasi sesi tagihan ini.' : undefined}
      required
    />
  )
}

Batasan: Komponen ini dikhususkan untuk elemen <input>; belum mencakup input berjenis dropdown <select> atau <textarea>.

7. Penerapan Komponen pada Halaman Aplikasi

Ketiga komponen reusable telah diterapkan secara nyata pada alur Single Page Application Share.Bill tanpa merusak rute dan fitur PWA yang telah dibangun pada Tugas 5a:

7.1 Halaman Beranda (src/pages/Home.tsx)

Menggunakan komponen <Card> untuk membungkus deskripsi pengenalan aplikasi ("Split your bill, simply.") dan komponen <Button variant="primary"> yang dibungkus Link dari React Router untuk navigasi mulus ke rute /create-bill.

Gambar 1. Tangkapan layar aktual Halaman Beranda (Home) dengan komponen Card dan Button varian primary.

7.2 Halaman Buat Tagihan — Kondisi Normal (src/pages/CreateBill.tsx)

Mengorganisasikan seluruh formulir dalam 3 buah komponen <Card>: Informasi Tagihan (berisi <FormField> normal dengan helper text), Anggota (berisi <Button variant="secondary">), dan Daftar Menu (berisi <Button variant="secondary">).

Gambar 2. Tangkapan layar aktual Halaman Buat Tagihan dalam kondisi normal menampilkan Card, FormField, dan Button secondary.

7.3 Halaman Buat Tagihan — Kondisi Error dan Disabled

Ketika pengguna memfokuskan input "Nama tagihan" lalu meninggalkannya dalam keadaan kosong (event onBlur), <FormField> secara reaktif menampilkan bingkai merah dan teks galat "Nama tagihan wajib diisi." dengan role="alert". Di bagian bawah, tombol "Hitung Tagihan" tampil dalam kondisi nonaktif (disabled, opasitas 0.55).

Gambar 3. Tangkapan layar aktual kondisi error pada FormField (bingkai merah & alert) dan Button disabled.
